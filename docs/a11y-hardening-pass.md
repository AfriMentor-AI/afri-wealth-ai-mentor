# A11y Hardening Pass (O5.2)

Date: 2026-08-30
Scope: Frontend (Next.js 14.2 PWA) — WCAG 2.1 AA, automated + structural review.
Baseline: audit pass O5.1 (axe: 0 critical / 0 serious across 9 static pages).

## Objective

Close the remaining WCAG 2.1 AA surface exposed in O5.1's recommendations and
clear the two `next build`/`next lint` warnings that were blocking a clean CI
gate. No contrast or color changes were made this pass (O5.1 covered those;
token contrast already passes AA at 4.5:1+ in both themes).

## Changes

### Frontend

- **Chat log & composer labels** — `frontend/app/(app)/chat/page.tsx`
  - Message thread container now has `role="log"` with `aria-label="Chat with <mentor>"`,
    so new messages are announced (WCAG 4.1.3 / ARIA live region for conversation).
  - Composer `textarea` gained `aria-label="Message <mentor>"` (WCAG 1.3.1, 4.1.2).
- **Daily action selected state** — `frontend/app/(app)/goals/action/page.tsx`
  - Option cards expose `aria-pressed={activeState === c.id}`, so the selected
    choice is conveyed to SR users, not only by border color (WCAG 1.3.1, 1.4.1).
- **Goal title input** — `frontend/app/(app)/goals/page.tsx`
  - Bare placeholder-only input wrapped in a labeled `<label>`; persistent visible
    "Goal title" text replaces reliance on placeholder (WCAG 1.3.1, 3.3.2).
- **Library search** — `frontend/app/(app)/library/page.tsx`
  - Search input wrapped in `<label>` with an `sr-only` visible-name equivalent,
    so the control has an accessible name (WCAG 1.3.1, 4.1.2).
- **Intake (step 3) profile fields** — `frontend/app/intake/page.tsx`
  - Name / Business name / Location switched from placeholder-only to labeled
    inputs with persistent "Your name", "Business name", "Location" labels
    (WCAG 1.3.1, 3.3.2); placeholders kept as examples.
- **Progress heatmap** — `frontend/app/(app)/progress/page.tsx`
  - Grid of colored `<div>` cells (visual-only) wrapped with:
    - `sr-only` text summary of what the heatmap conveys;
    - `aria-hidden="true"` on the decorative grid (WCAG 1.1.1, 1.3.1).
  - Also fixed a latent JSX imbalance (`<div>`/`<>`) in the heatmap branch found
    while re-auditing — this previously rendered an unclosed structural block.
- **Welcome carousel** — `frontend/app/welcome/page.tsx`
  - Carousel body is `aria-live="polite"` so slide changes are announced (WCAG 4.1.3).
- **Feedback survey dialog** — `frontend/components/FeedbackSurveyModal.tsx`
  - `role="dialog"` + `aria-modal="true"` + `aria-labelledby` already present; now
    also moves focus to the close button on open and closes on Escape
    (WCAG 2.1.1, 2.4.3 / APG dialog pattern).
- **Font loading** — `frontend/app/layout.tsx`, `frontend/app/globals.css`
  - Duplicated Google Fonts stylesheets (CSS `@import` in `globals.css` *and* a
    `<link>` in `layout.tsx`) collapsed to `<link>`-only with
    `rel="preconnect"` for `fonts.googleapis.com`/`fonts.gstatic.com` and
    `display=swap` on both families. Removes a double network fetch and lets the
    font CSS fetch in parallel with app CSS instead of serially.
  - This also removes the `@next/next/google-font-display` lint warning.

### Backend — `services/chat-orchestration-service`

- **`app/rag.py`**, **`app/llm.py`**: removed a duplicated `httpx.AsyncClient`
  init (the first one was created and immediately discarded, wasting a connection
  during first call).
- **`app/rag.py`**: RAG POST `timeout` raised `1.5s → 5.0s` (read threshold).
  1.5s is below the observed p95 of the RAG pipeline under load and caused
  spurious chat failures; `connect=0.3` retained so a dead downstream still fails
  fast. Chat-orchestration total budget unchanged (service still fails fast
  overall — this only affects the per-RAG-call step).

## Known limitations / next steps

1. **Dialog focus trap**: the feedback modal moves focus in and closes on Escape,
   but does not yet trap Tab focus inside the dialog, and focus isn't restored to
   the trigger on close. Full APG focus-trap + `:focus-visible` restore is a
   follow-up (owned with the modal work in the frontend roadmap).
2. **Language/`lang` attributes**: pages don't declare regional language vs. the
   Pidgin/swahili-flavored copy; worth a content pass, not a code break.
3. **CLI-derived tooling files**: `frontend/tsconfig.json` (`jsx: preserve`) and
   `frontend/next-env.d.ts` are regenerated by every `next build`/`next dev` and
   were reverted from the diff; consider the tooling-driven difference as
   expected and ignore in CI.
